Smoke-Landing Pipeline Map

How code written outside the corporate boundary gets scanned, run in staging on Google Cloud, signed, and pulled into the on-prem boundary after two human approvals.

One commit's path

  1. OutsidePushDeveloper pushes to an app repo's default branch.
  2. AutomaticGateScan, build, scan the image, apply policy.
  3. AutomaticStagingSigned image runs on Cloud Run with test keys; smoke check and ZAP scan.
  4. Human 1ReleaseAn approver promotes the exact digest to smoke-release.
  5. Human 2 · insideBoundary approvalGitLab verifies, re-scans; someone other than the author approves.
  6. InsideOn-prem runPodman refuses anything unsigned.

Blocked at the gate: any critical or high finding stops the run, files a GitHub issue in the app repo, and the issue closes itself once a later commit no longer has the finding.
